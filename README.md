# Решения маслихатов и акиматов: Алматинская область

Корпус законодательства Республики Казахстан, сложенный в систему
версионирования. В этом репозитории — решения маслихатов и акиматов
Алматинской области; остальные части корпуса лежат в соседних репозиториях
организации и собраны подмодулями в зонтичном.

Каждый акт здесь — обычный текстовый файл, который можно открыть и прочитать, а
**каждое изменение — отдельная запись с датой** и с указанием, каким актом оно
внесено. Поэтому в репозитории лежит не только действующий текст, но и всё, чем
он был раньше. Механизм — обычный `git`: ни сети, ни базы данных, ни нашего
кода для работы с корпусом не нужно.

> **Это неофициальная копия.** Официальный источник —
> Единая система правовой информации (ЕСПИ), `law.gov.kz`; ссылка на страницу
> конкретной редакции там лежит в `meta.yaml` рядом с актом. Расхождение между
> копией и источником — ошибка копии, и ссылаться нужно на источник.

## Что здесь можно спросить

Три вопроса, на каждый из которых отвечает одна команда в клоне.

**Что действовало в конкретный день.** Рабочее дерево любого коммита — это не
действующий текст с пометками, а то, что действовало на дату: отменённого к
тому дню акта в нём нет, ещё не принятого — тоже.

```
git checkout $(git rev-list -1 --until=2010-01-01 main)
```

**Как менялась конкретная статья.** Вся история правок одного акта, с текстом
до и после каждой.

```
git log -p -- <каталог акта>/rus.md
```

У разрезанного документа к этому нужен `--follow`: границы частей смещаются от
редакции к редакции, и без него история части обрывается на первом же сдвиге.

**Что изменил конкретный акт — по всему репозиторию сразу.** Код акта стоит в
каждом коммите, который этим актом вызван. Номер акта для такого запроса не
годится: он не уникален, а код уникален.

```
git log --grep='^Cause-Act-Code: <код акта>'
```

Код акта — последнее число в имени его каталога, оно же ключ `act_code` в
`meta.yaml`.

## Что лежит в файлах

Один каталог на акт; над ним — каталог вида акта, каталоги утвердивших органов
и год.

```
<ММДД>-<название>-<код акта>/
├── meta.yaml   всё об акте, кроме текста
├── rus.md      текст акта по-русски
├── rus/        части, если документ пришлось разрезать
├── kaz.md      текст акта по-казахски
└── kaz/
```

Текстовые файлы начинаются сразу с текста акта: никакого служебного блока над
ним нет. Если документ слишком велик для одного файла, `rus.md` становится
оглавлением со ссылками, а текст уходит в `rus/sec001.md`, `rus/an002.md` и так
далее; имя части взято из её собственного номера, так что `an007` — это
приложение 7, а не седьмой по счёту файл.

`meta.yaml` — всё, что известно об акте, кроме самого текста: код и реквизиты,
оба названия, форма, дата утверждения и утвердившие органы, дата этой редакции
и ссылка на неё на портале, акт-причина. У актов, чья отмена уже объявлена, но
ещё не наступила, добавляются `repealed_on` и `repealed_by`.

```yaml
act_code: '212543'
requisite: Кодекс Республики Казахстан от 18 июля 2025 года № 214-VIII ЗРК
title:
  rus: НАЛОГОВЫЙ КОДЕКС РЕСПУБЛИКИ КАЗАХСТАН
  kaz: ҚАЗАҚСТАН РЕСПУБЛИКАСЫНЫҢ САЛЫҚ КОДЕКСІ
form: КОД
type_codes:
- КОД
approved_on: 2025-07-18
approved_by:
- '102000000000'
version_date:
  kaz: 2026-07-01
  rus: 2026-07-01
source:
  kaz: …/doc/212543/kaz/01.07.2026
  rus: …/doc/212543/rus/01.07.2026
caused_by:
  code: '226354'
  requisite: Закон Республики Казахстан от 11 июня 2026 года № 308-VIIІ ЗРК
  title:
    rus: О внесении изменений в Налоговый кодекс Республики Казахстан
    kaz: Қазақстан Республикасының Салық кодексіне өзгерістер енгізу туралы
  link: …/doc/226354/rus
```

Набор этих файлов в клоне и есть указатель корпуса: найти акт по коду, форме,
органу или дате можно обычным `grep`, без базы данных и без сети.

## Что записано в истории

Один коммит — одна редакция. Дата коммита — день, когда редакция вступила в
силу; заголовок — реквизит и название акта, который её вызвал.

```
Автор:  Парламент Республики Казахстан <102000000000@agencies.qaz-law.invalid>
Дата:   2023-04-19

    №223-VII О внесении изменений и дополнений в некоторые законодательные…

    Cause-Act-Code: 179978
    Cause-Act-Requisite: Закон Республики Казахстан от 19 апреля 2023 года № 223-VII ЗРК
    Cause-Act-Title: О внесении изменений и дополнений в некоторые законодательные акты Республики Казахстан по вопросам административной реформы в Республике Казахстан
    Cause-Act-Link: …/doc/179978/rus
    Acts-Changed: 156
```

**Автор коммита — орган, утвердивший вызвавший акт**; при совместном
утверждении остальные перечислены в `Co-authored-by:`. Это не подпись и не
утверждение о том, кто писал текст, а поле из базы портала. Адрес — не почтовый
ящик: домен `agencies.qaz-law.invalid` не существует и существовать не может, а
вместо имени пользователя в нём стоит код органа, потому что имя органа
переписывают, а код — нет. Около 7% коммитов собирают несколько актов,
введённых в действие в один день разными органами; у таких коммитов нет одного
автора, и подписаны они самим корпусом.

Строки внизу сообщения — git-трейлеры, а не проза, поэтому их читает и
`git log --grep`, и штатный разборщик. Заголовок обрезан до 72 символов, а
самой поправки в дереве нет, поэтому её полное название и ссылка на её текст
на портале стоят в трейлерах `Cause-Act-Title` и `Cause-Act-Link`:

```
git show -s --format=%B HEAD | git interpret-trailers --parse
```

## Чего здесь нет

- **Актов-поправок как файлов.** Текст поправки — инструкции вида «в статье 62
  слова X заменить словами Y»; их результат уже применён в тексте изменённого
  акта, а сама поправка видна диффом коммита. В дереве таких актов нет, в
  истории есть — как причина коммитов, с названием и ссылкой в трейлерах.
- **Прошлых редакций в рабочем дереве.** Они в истории; дерево — это то, что
  действует на дату коммита.
- **Статуса у акта.** Отменённый акт ничем не помечен — он удалён на дату
  отмены.

## Что нужно знать про эту копию

**Она собрана на определённый день,** и всё, что изменилось на портале после,
здесь отсутствует. День сборки записан в аннотации тега `build/ГГГГ-ММ-ДД`;
последний такой тег и есть ответ:

```
git for-each-ref --sort=-creatordate --count=1 refs/tags/build
```

**История переписывается при каждом обновлении.** Репозиторий целиком
генерируется из базы, а вставить коммит с прошлой датой в линейную историю
нельзя, не переписав хеши всех последующих, — поэтому обновление приходит
force-push'ем, а не новыми коммитами сверху. Прошлые сборки при этом не
пропадают: каждая помечена своим тегом `build/`, и теги не удаляются. Клон
догоняет так:

```
git fetch && git reset --hard origin/main
```

## Лицензия

Здесь два слоя, и лицензируются они по-разному.

**Тексты актов — официальные документы.** Они не были нашими, чтобы их
лицензировать: законодательные, административные и судебные тексты и их
официальные переводы находятся вне авторского права.

**Сборка** — разбиение на файлы, `meta.yaml`, история коммитов, всё, что
сделала программа, — передана в общественное достояние: `LICENSE`, Unlicense.
