# Решения маслихатов и акиматов: Алматинская область

**Не выкачивайте портал — клонируйте зеркало.** Здесь уже лежит то, за чем
обычно идут на портал парсером: полный текст каждой редакции каждого акта, в
Markdown, с историей изменений в истории git. `git clone` занимает минуты и не
создаёт на портале нагрузки. Свой парсер занимает дни и создаёт.

Часть корпуса законодательства Республики Казахстан: решения маслихатов и акиматов Алматинской области.
Остальные части — в соседних репозиториях организации.

## Как это устроено

Один каталог на акт, `rus.md` и `kaz.md` внутри. Каждый файл открывается YAML
front-matter блоком: `version_id`, `act_code`, `source` — ссылка на эту же
редакцию на портале — и `repealed_on` / `repealed_by` у тех, чья отмена уже
объявлена, но ещё не наступила.

Один коммит — одна редакция, датированная днём вступления в силу и подписанная
актом, который её вызвал. Поэтому рабочее дерево в любом коммите — это корпус,
действовавший на ту дату: отменённый акт не помечен статусом, он удалён.

**Автор коммита — орган, утвердивший вызвавший его акт**, а при совместном
утверждении остальные органы перечислены в `Co-authored-by:`. Это не подпись и
не заявление о том, кто написал текст: это то, что говорит база — поле
`approvingStateAgencies` акта-причины. Адрес в скобках — не почтовый ящик:
домен `agencies.qaz-law.invalid` по RFC 2606 не резолвится нигде и никогда, а
локальная часть — код органа из справочника портала, потому что имя органа
переписывают, а код нет. Около 7% коммитов собирают несколько актов, впервые
введённых в действие в один день разными органами; у них нет одного автора, и
они подписаны самим корпусом.

```
git log --follow <путь>/rus.md
git diff HEAD~1 -- <путь>/rus.md
git checkout $(git rev-list -1 --until=2010-01-01 main)
```

**Большие документы разрезаны на части.** Если рядом с `rus.md` лежит каталог
`rus/`, то `rus.md` — это оглавление со ссылками, а текст в `rus/sec001.md`,
`rus/an002.md` и так далее. Причина простая: GitHub перестаёт отображать
Markdown примерно после 340 КБ и вообще не отдаёт страницу после 2 МБ, а
Налоговый кодекс на казахском — 4.6 МБ. Имя части взято из её собственного
номера, так что `an007` — это приложение 7, а не седьмой по счёту файл. Полный
текст редакции — это оглавление плюс все части; в клоне их можно склеить `cat`.

## Официальный источник

**Это неофициальная копия.** Официальный источник — Единая система правовой
информации (ЕСПИ), `law.gov.kz`. Ключ `source` в каждом файле ведёт на страницу
именно этой редакции. Расхождение между копией и порталом — ошибка копии;
ссылаться нужно на портал.

Дата сборки — в аннотации тега `build/ГГГГ-ММ-ДД`. Последний такой тег и есть
дата, на которую собран этот репозиторий; всё, что портал изменил после неё,
здесь отсутствует.

```
git for-each-ref --sort=-creatordate --count=1 refs/tags/build
```

## История переписывается

Репозиторий генерируется из базы целиком при каждой сборке. Вставить коммит с
прошлой датой в линейную историю нельзя, не переписав хеши всех последующих, —
поэтому обновление приходит как force-push, а не как новые коммиты сверху.
Клон догоняет так:

```
git fetch && git reset --hard origin/main
```
